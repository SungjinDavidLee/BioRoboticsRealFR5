# 평가 중 생긴 문제

## 1. 제어판이 UDP 그리퍼 값을 무시함

**증상.** 오후부터 판마다 같은 자리에서 멈췄다. 정책은 잡는 높이(z 130 mm 근처)까지 정상으로 내려가 닫으라고 했는데, 2.5 s 동안 그리퍼 위치가 1000(완전 열림)에서 움직이지 않아 평가 도구가 그 자리에 섰다.

```
멈춤: 그리퍼가 2.5 s 안에 닫히고 멈추지 않았다(위치 1000, 명령 전 1000, 명령 0)
```

**가르기.** 그리퍼에 명령이 가는 길이 두 가지라 하나씩 시험했다.

| 시험 | 결과 |
|---|---|
| 제어판 HTTP로 직접 (`POST /api/gripper {"pos": 500}`) | 0.2 s 뒤 움직이기 시작, 0.5 s에 500 도착 — 그리퍼와 위치 읽기는 정상 |
| 평가와 같은 UDP 길 (`tools/grip_udp.py`) | 추종 중·연결 정상인데 목표가 1000에서 바뀌지 않음 |

팔 관절 목표는 받아들이면서 그리퍼 값만 버리고 있었다. 2.5 s 검사는 오작동이 아니라 이 상태를 잡은 것이다.

**해결.** 제어판을 끄고 다시 띄우자 UDP 그리퍼 값이 0.2–0.3 s 만에 적용됐다. 왜 그 상태가 됐는지는 아직 모른다.

**재시작할 때 주의.** 이전 제어판이 살아 있는데 새로 띄우면, 새 쪽은 제어기 상태 패킷을 받지 못하고 20 s 뒤 끝난다. 제어판 하나가 제어기 연결을 혼자 쥐기 때문이다.

```bash
pgrep -af fr5d          # 돌고 있는 제어판 확인
kill <PID>              # 끄고 15 s 기다린 뒤 새로 띄운다
```

평가 중 같은 멈춤이 나오면 `grip_udp.py`로 먼저 가른다. 이 문제로 멈춘 판은 정책과 무관하므로 결과에 넣지 않는다.

## 2. 시작 장면에서 링을 못 찾는 판

평가 도구는 판정을 위해 자동 수집기의 3인칭 인식으로 링 칸을 찾는다. 링을 못 찾은 판에서는 "칸 위로·꽂기·끝 장면"을 자동으로 정하지 못했다.
그런 판은 사람이 결과를 정했다. 못 찾는 원인(가림, 색 문턱 등)은 따로 가르지 않았다. 학습 데이터에서도 첫 프레임에서 링을 다시 찾은 판은 200판 중 97판이었다.

## 3. 평가 조건 차이 — 밝기

자동 수집은 판마다 노출을 고쳐 3인칭 밝기를 147(fr5rec 밝기 표시)에 맞췄다. 평가 도구에는 이 기능이 없고, 평가 중 밝기는 약 200이었다(운영자 관찰).
결과에 얼마나 영향을 줬는지는 재지 않았다.
